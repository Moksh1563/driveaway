# Deploying Driveaway

Three free services, about 20 minutes:

| Part | Service | What runs there |
|---|---|---|
| Database | MongoDB Atlas | cars, users, bookings, uploaded car photos |
| API | Render | the Express server in `server/` (configured by `render.yaml`) |
| Website | Vercel | the React site (configured by `vercel.json`) |

Sign in to Render and Vercel **with the GitHub account that owns this repository** (Moksh1563), so they can see it.

---

## 1. Database: MongoDB Atlas

1. Go to <https://www.mongodb.com/cloud/atlas/register> and create a free account.
2. Create a cluster: choose **M0 (Free)**, provider **AWS**, region **Mumbai (ap-south-1)**.
3. **Database Access → Add New Database User**: pick a username, click **Autogenerate Secure Password**, copy the password somewhere safe, role **Read and write to any database**.
4. **Network Access → Add IP Address → Allow Access from Anywhere** (`0.0.0.0/0`). Render's free servers don't have a fixed address.
5. **Database → Connect → Drivers** and copy the connection string. It looks like
   `mongodb+srv://USER:<db_password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`
   Replace `<db_password>` with your password, and add the database name `driveaway` before the `?`:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/driveaway?retryWrites=true&w=majority`

### Fill the database (once)

From this project folder on your computer, in PowerShell:

```powershell
$env:MONGO_URI = "paste-your-full-connection-string-here"
cd server
npm run seed
Remove-Item Env:MONGO_URI
```

This creates the 48-car fleet, the demo admin and customer accounts, promo codes and sample bookings in Atlas.
Save the two passwords it prints. Setting `$env:MONGO_URI` takes priority over `server/.env`, so your local
database is untouched; `Remove-Item Env:MONGO_URI` switches the window back to it, so a later command
can't reach Atlas by accident.

The seed first prints the database it is about to wipe and what is in it. A brand-new, empty Atlas database
is seeded straight away. Once it holds data, the seed refuses to run against it unless `SEED_CONFIRM` is
set to the database name (`$env:SEED_CONFIRM="driveaway"`), because re-seeding **deletes every user,
booking and uploaded photo**. To change the cars later, use `syncFleet` instead (see **Good to know**).

## 2. API: Render

1. Go to <https://dashboard.render.com> and sign up with GitHub.
2. **New + → Blueprint**, pick the `driveaway` repository. Render reads `render.yaml`.
3. Render asks for the values it can't fill itself:
   - `MONGO_URI`: your Atlas connection string from step 1
   - `CLIENT_URL`: leave empty for now (you'll add it in step 4)
   - `PUBLIC_API_URL`: leave empty (only needed if photo or unsubscribe links ever show the wrong address; see step 4)
   - `BREVO_API_KEY`, `EMAIL_FROM`, `EMAIL_TEAM`: for emails, see **Booking emails** below (leave empty to skip emails)
   `JWT_SECRET` is generated by Render automatically, and `NODE_VERSION` is pinned to 24.
4. Click **Apply** and wait for the deploy to finish (2–4 minutes).
   Render's health check is `/api/health`: it answers 200 `{"status":"ok","db":"up"}` only while the
   API is connected to MongoDB, so a wrong `MONGO_URI` shows up as a failed deploy (the log says why).
5. Copy the service URL, e.g. `https://driveaway-api.onrender.com`. Opening it should show
   `{"message":"Driveaway API Running 🚗"}`, and `/api/health` on it should show `{"status":"ok","db":"up"}`.

After that, Render deploys each push to `main` **only once its GitHub checks pass** (`autoDeployTrigger: checksPass`
in `render.yaml`; in the dashboard: Settings → Auto-Deploy → *After CI checks pass*). The checks are the lint, build
and API tests in `.github/workflows/ci.yml`, so a commit that breaks them never reaches the live API. If you ever
delete that workflow, set Auto-Deploy back to *On commit*, or Render stops deploying. Vercel still deploys every push.

## 3. Website: Vercel

1. Go to <https://vercel.com/new> and sign up with GitHub.
2. Import the `driveaway` repository. Keep the project name **driveaway**: until `CLIENT_URL` is set, the API
   only accepts the website at `https://driveaway.vercel.app` (plus localhost).
3. Framework is detected as **Vite**; leave the build settings as they are.
4. Under **Environment Variables** add:
   - `VITE_API_BASE_URL` = your Render URL + `/api`, e.g. `https://driveaway-api.onrender.com/api`
   - optional: `VITE_SITE_URL` = your Vercel address (used in WhatsApp invoices the browser builds when the API can't; without it the site uses its own address)
5. Click **Deploy**. Copy the site address, e.g. `https://driveaway.vercel.app`.

`vercel.json` sends a **Content-Security-Policy** header. It only lets the site call APIs on
`https://*.onrender.com` (`connect-src`). If your API lives anywhere else, add that address to
`connect-src` in `vercel.json`, or the site can't reach it.

## 4. Connect them

In Render: your service → **Environment** → set `CLIENT_URL` to your Vercel address (no trailing slash) → **Save**.
Render redeploys automatically.

`CLIENT_URL` does two jobs:
- **CORS**: browsers may call the API only from exactly these addresses, `https://<VERCEL_PROJECT_PREFIX>.vercel.app`
  (default `driveaway`) and localhost. Several sites can be listed, separated by commas.
- **Links**: password reset links, the links in booking, alert and offer emails, and the site links in
  WhatsApp invoices point to the first `CLIENT_URL`. Without it they fall back to
  `https://<VERCEL_PROJECT_PREFIX>.vercel.app` and the API logs a warning at startup.

Two optional settings:
- `PUBLIC_API_URL` = your Render URL (e.g. `https://driveaway-api.onrender.com`). Uploaded photos and
  unsubscribe links are built from the address each request came in on; set this only if they show the wrong host.
- `VERCEL_PREVIEW_SUFFIX` = `-<your-team-slug>.vercel.app` lets Vercel **preview** deployments
  (`https://driveaway-<anything>-<your-team-slug>.vercel.app`) reach the API. Leave it empty unless you need
  previews: anyone can name a Vercel project to look like a preview address, so exact `CLIENT_URL` entries are safer.

Open the Vercel address: the home page should show the paint swatches and cars. Sign in as `admin@driveaway.com`
with the password `npm run seed` printed, to check the admin panel.

## 5. Booking emails (optional)

Render's free plan blocks email over SMTP, so Gmail settings don't work there. The API sends through
**Brevo's** web API instead (free: 300 emails a day, no domain needed).

1. Sign up at <https://www.brevo.com> (free plan).
2. **Senders, domains & IPs → Senders → Add a sender**: enter the address emails should come from (your Gmail is fine)
   and click the confirmation link Brevo emails you.
3. **SMTP & API → API keys → Generate a new API key**. Copy it.
4. In Render: your service → **Environment** → add
   - `BREVO_API_KEY` = the key from step 3
   - `EMAIL_FROM` = the sender address from step 2
   - optional `EMAIL_TEAM` = where contact-form messages should go (defaults to `EMAIL_FROM`)

   → **Save**. Render redeploys.
5. Sign in to the website as the admin, open **Admin → Overview**, and click **Send test email** on the *Booking emails* row.
   It sends to the admin's own address and shows Brevo's reason if anything is wrong.

The API emails booking confirmations (with the PDF invoice), payment receipts, status changes, availability
alerts, password reset links, promo-code broadcasts (each with a one-click unsubscribe link) and contact-form
messages to the team. Without email, **Forgot password** can't deliver its link in production (on your own
computer the link is also printed in the server console).

Emails from a Gmail address sent through Brevo can land in spam at first; a sender on your own domain fixes that later.
On your own computer you can use Gmail SMTP instead: `EMAIL_USER` + `EMAIL_PASS` (a Gmail app password) in `server/.env`.

## Good to know

- **First load can take ~50 seconds.** Render's free plan sleeps after 15 minutes without visitors and wakes on
  the next request. The website pings `/api/health` on start and shows a "waking up the server" banner if
  the API is slow to answer; the site waits up to 65 seconds for each answer.
- **Photos uploaded in the admin panel are stored in MongoDB**, so they survive Render restarts and deploys.
  They count toward Atlas's free storage (512 MB on M0), up to 5 MB each, and stay in the database when a
  car is deleted or its photos are replaced. The 48 fleet cars use Wikimedia Commons links.
- **Changing the website's API address** requires a redeploy on Vercel (Vite bakes `VITE_API_BASE_URL` into the build).
- **Updating the fleet later**: edit `server/data/fleet.js`, then from `server/`, with `$env:MONGO_URI` set to Atlas:
  - `node scripts/syncFleet.js --dry-run` lists every change and writes nothing.
  - `node scripts/syncFleet.js` adds missing cars and updates specs. Users, bookings, statuses, ratings and the
    prices and photos an admin changed are kept, and cars that are not in the fleet data are listed, not deleted.
  - `--overwrite-prices` / `--overwrite-photos` replace prices / photos with the fleet data.
  - `--prune` deletes cars that are not in the fleet data, except any car that has ever been booked.
  - Then `Remove-Item Env:MONGO_URI`.
- **Editing the inline script in `index.html`** (the theme script in `<head>`) means updating its hash in
  `vercel.json`'s `script-src`, or browsers will block it. Print the new hash with (it hashes the LF version,
  which is what Vercel builds; `.gitattributes` keeps `index.html` LF on every checkout):
  `node -e "const h=require('fs').readFileSync('index.html','utf8').replace(/\r\n/g,'\n').match(/<script>([\s\S]*?)<\/script>/)[1];console.log(require('crypto').createHash('sha256').update(h).digest('base64'))"`
- **Forgotten admin password**: use **Forgot password** on the sign-in page (needs email in production; see step 5).

## Security

- No passwords are stored in this repository. `npm run seed` prints new random passwords for
  `admin@driveaway.com` and `customer@example.com` (or uses `SEED_ADMIN_PASSWORD` / `SEED_USER_PASSWORD` from your environment).
  Save them when they are printed.
- The seed never wipes a database that has users or bookings, or a non-empty remote database, unless
  `SEED_CONFIRM` names that database. Set it only for the one run.
- `JWT_SECRET` signs sign-in tokens and the unsubscribe links in offer emails. Changing it signs everyone out
  and makes links in emails already sent stop working.
- Never commit `server/.env`. It is already in `.gitignore`.
